# Moxie Timer: MCP review and product council (2026-11-03)

## 1. Where the app stands today

The widget talks to Moxie's **Public REST API** (API key, `X-API-KEY`). That API has these gaps, and they cause most of the friction:

| Need | Public API | Moxie MCP (`https://pod01.withmoxie.com/mcp`) |
|---|---|---|
| Moxie's own live timer | none: the widget keeps a local timer and posts a finished entry | `timer_get`, `timer_start` (client, project, task **or ticket**, billable, notes), `timer_pause`, `timer_resume`, `timer_stop`, `timer_discard` |
| List / edit / delete time entries | none (this is why "hold for review" exists) | `time_entries_list`, `time_entries_update` (incl. `ticketId`, `billable`, `clearFields`), `time_entries_delete` |
| Ticket on a time entry | none: the app folds "Ticket #12" into the notes | first-class `ticketId` on timer and entries |
| Billable flag | undocumented, sometimes ignored | `billable` on `timer_start` and `time_entries_update` |
| "What should I do now?" | the app ranks tasks itself | `dashboard_daily_focus` (Respond / Deliver / Grow), `dashboard_needs_attention` |
| Task priority / dates | read only | `tasks_update` with `priority` (Low … Urgent), `dueDate`, `startDate`, `statusId` |
| Ticket → task | none | `tickets_create_task` (comments stay in sync) |
| Checklists / subtasks | none | `task_checklist_list` / `task_checklist_set`, `task_subtasks_list` |
| Resolve names to IDs | by exact name only | `search` |

**Auth:** the MCP server is OAuth only (remote Streamable HTTP + OAuth, workspace-scoped consent, "Read and write" or per-area access). No API key. It needs a Pro or Teams workspace with MCP enabled by the owner. In this session the Moxie connector returned *503 "Account authorization is temporarily unavailable"*, so tool calls were not tested live; schemas above were read from the identical tool set exposed through the FWS MCP.

## 2. Recommendation

**Make the widget an MCP client and let Moxie's timer be the single source of truth.**

1. **OAuth sign-in** (native, no server): discover `/.well-known/oauth-protected-resource` → authorization server metadata → dynamic client registration → `ASWebAuthenticationSession` with PKCE → store refresh token in the Keychain. Keep the API key as a fallback for workspaces without MCP.
2. **Transport:** JSON-RPC 2.0 over HTTPS POST (`initialize`, `tools/call`), `Mcp-Session-Id` header. A ~200-line `MoxieMCP` actor next to `MoxieAPI`.
3. **Timer mirror:** Start/pause/resume/stop in the widget call `timer_*`; poll `timer_get` every ~30 s (and on wake) so a timer started in the Moxie web app, or by Claude, shows in the pill. That removes the class of bug where the Focus timer and the Timer tab disagree, and the widget, the web app and Claude all show the same clock.
4. **Edits instead of holding:** with `time_entries_update` / `delete`, "hold for review" can become "send now, fix later". Review then reads real entries with `time_entries_list` and patches them; nothing is lost if the Mac sleeps.
5. **Tickets as equals:** start the timer with `ticketId`; offer "Make a task from this ticket" with `tickets_create_task`.
6. **Urgency from Moxie:** blend `dashboard_daily_focus` + `dashboard_needs_attention` into the "Most urgent" list (keep the local ranking as a fallback and tie-breaker).
7. **Tiny first step → checklist:** write the AI first step to the task with `task_checklist_set`, so it's in Moxie too.

Guardrails from Moxie's docs to respect: `tasks_update` and ticket comments can notify clients (send `confirmNotifications` only on explicit user action); public ticket comments email the client; `timer_discard` and `time_entries_delete` are permanent; invoiced entries can't be edited.

## 3. Council

Four voices, one goal: connected, fluid, simple, very productive, for someone with ADHD.

**ADHD coach.** The fewer decisions between "I should work" and "the clock is running", the better. The reminder now shows the most urgent items with one click to start: that's the right shape. Next: when the reminder fires, *pre-select* the top item so Enter starts it. Confetti and the strikethrough matter: dopamine at completion is what makes you come back. Don't add more settings; add better defaults.

**Product designer.** Three places say "what am I doing": Focus, Timer and the pill. They must never disagree. Make Focus the only place you *choose* work; Timer becomes the details/edit view of the same session. One list, Todoist-style, everywhere: Up next, Tasks, the reminder. Tickets and tasks look the same, with a badge. Kill "Just focus" eventually: if every focus has a client, Review shrinks.

**Freelancer (Moxie power user).** My billing is in Moxie, so if the widget's timer isn't Moxie's timer I'm double-checking twice. MCP fixes it. I also want: ticket work billed to the ticket, not "Ticket #12" in the notes; a weekly "unbilled hours by client" glance; and when I finish a ticket, an optional private comment with what I did (`ticket_comments_create`, private by default).

**Engineer.** MCP is a beta with 230+ tools and OAuth; wrap it behind one protocol (`MoxieBackend`) with two implementations (REST, MCP) so the app keeps working if MCP is down (it was down today). Poll, don't stream. Cache IDs from `search`. Write tests around the session state machine: start → switch task → stop, with and without a client, to lock in today's bug fix.

**Agreed order**

1. ✅ (this branch) Fix time leaking between tasks; tickets in the composer; Todoist-style list with confetti and undo; urgent items in the reminder.
2. ✅ (feat/mcp-live-timer) MCP sign-in + `timer_*` mirror (biggest win: one clock everywhere).
3. Ticket-native time (`ticketId`) and `tickets_create_task`.
4. Review on real entries (`time_entries_list` / `update`), then retire hold-for-review as the default.
5. Moxie dashboard feeds in "Most urgent" / "Pick for me"; first step → checklist.
6. Small: Enter starts the top urgent item in the reminder; "New ticket" from the composer's Ticket chip.
